# i18n Guide

## Overview

The app uses a lightweight custom i18n layer — no external library required. It lives in `src/lib/i18n/`.

| File | Role |
|---|---|
| `src/lib/i18n/index.tsx` | `I18nProvider`, `useTranslation` hook, `t()` helper |
| `src/lib/i18n/locales/en.json` | English dictionary (source of truth) |
| `src/lib/i18n/locales/es.json` | Spanish stub |
| `src/components/i18n/LocaleSwitcher.tsx` | Dropdown to toggle locale |

## How `t()` works

```tsx
const { t } = useTranslation()
t("nav.home") // → "Home" (en) or "Inicio" (es)
```

Missing keys fall back to English, then to the raw key string — so the UI never breaks.

## Adding a new key

1. Add the key + English string to `src/lib/i18n/locales/en.json`:
   ```json
   "feature.myNewString": "My new string"
   ```
2. Add the translated value to every other locale file (or leave it out — English fallback kicks in):
   ```json
   "feature.myNewString": "Mi nueva cadena"
   ```
3. Use it in any client component:
   ```tsx
   const { t } = useTranslation()
   <p>{t("feature.myNewString")}</p>
   ```

## Adding a new locale

1. Create `src/lib/i18n/locales/<code>.json` (copy `en.json` as a template).
2. Add the locale to the `Locale` union type and `dictionaries` map in `src/lib/i18n/index.tsx`:
   ```ts
   import fr from "./locales/fr.json"
   export type Locale = "en" | "es" | "fr"
   const dictionaries = { en, es, fr }
   ```
3. Add an entry to `localeOptions` in `src/components/i18n/LocaleSwitcher.tsx`.

## Locale persistence

The selected locale is stored in `localStorage` under the key `locale` and restored on page load. No cookies, no server-side changes.

## LocaleSwitcher

Rendered inside `TopNav`. Styled identically to `ThemeToggle` — a ghost icon button that opens a dropdown menu.
